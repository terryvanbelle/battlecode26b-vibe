## 2. Implementation sketches (top 3)

### #1 `SYM_CHIRAL` (king only, round 1)

**Basis.**
- The engine builds the sensing list x outer, y inner. For chirality 1 it reverses y on HOR maps, x on VER maps, and both on ROT maps (GameWorld.java:746-792, switch at 767-781).
- `senseNearbyMapInfos` passes `robot.getChirality()` and only filters, so the order survives (RobotControllerImpl.java:672-691). New babies inherit the king's chirality (RobotControllerImpl.java:1017).
- The spec documents this order (specs.pdf p.9). The king sees r² 25 all round (UnitType.java:6), and its centre is at least 1 tile from every edge, so the list always spans at least 3 columns and 3 rows.

**Changes.**
- `Cfg.java`: `public static final boolean SYM_CHIRAL = false;`, with a comment noting that it makes play side-dependent, so mirror_check must run with it off.
- `King.java`, new pure function:
  ```java
  static int symFromOrder(MapInfo[] in) {
      int n = in.length; if (n < 4) return 0;
      MapLocation a = in[0].getMapLocation(), z = in[n - 1].getMapLocation();
      if (a.x == z.x) return 0;
      boolean xr = a.x > z.x;
      for (int k = 0; k + 1 < n; k++) {
          MapLocation p = in[k].getMapLocation(), q = in[k + 1].getMapLocation();
          if (p.x == q.x) { boolean yr = p.y > q.y; return xr ? (yr ? Sym.ROT : Sym.VER) : (yr ? Sym.HOR : 0); }
      }
      return 0;
  }
  ```
- In `King.sense()`, right after `infos` is read (King.java:100; s4d :78):
  ```java
  if (Cfg.SYM_CHIRAL && G.round <= 1 && !Sym.unique() && G.rc.senseRobot(G.rc.getID()).chirality == 1) {
      int s = symFromOrder(infos); if (s != 0) Sym.merge(s);
  }
  ```
  `Sym.merge` already rejects a disjoint result and counts a contradiction (Sym.java:48-51). The `publish()` at King.java:36 runs before `spawn()`, so every baby merges the mask on its first turn (Baby.java:34-35).
- Bundle #6 into `initialSymmetry` (King.java:90-95): replace the exact self-mirror test with `G.cheb(G.me, G.mirror(G.me, s)) <= 2`. Put the round 1-4 empty-centre check behind `Cfg.SYM_KINGSTART`.

**Bytecode.** The first column holds 1 tile, so the scan stops after 1-2 steps. Total is about 50 bytecode plus 25 for `senseRobot(own id)` (RULES.md:94), once per game. Afterwards `Sym.record` returns early on that side (Sym.java:26) and saves bytecode. The other side of that coin: a wrong mask could never be caught, which is why the test and the per-engine-version indicator check below matter.

**Unit test** (`test/ratbot/BotTest.java`, `testSymFromOrder`):
- Add a helper `engineOrder(c, chir, s)` that copies GameWorld.java:752-787: the box c±6 clipped to a 20x20 map; for chirality 1, reverse xs when `s != HOR` and ys when `s != VER`; keep tiles with d2 ≤ 25. Wrap each as `new MapInfo(l, true, null, false, false, 0, TrapType.NONE, false)`, the constructor the test already uses at :114.
- For centres (1,1), (10,10), (18,18) and (1,18) and each s: `symFromOrder(engineOrder(c,1,s)) == s` and `symFromOrder(engineOrder(c,0,s)) == 0`.
- A single-tile array returns 0.
- With `Sym.mask = ROT|VER`, merging HOR leaves the mask unchanged and sets `contradictions == 1`.

### #2 `SYM_HEAR_TILE` + `SYM_GOSSIP`

**Basis.**
- The engine delivers a squeak to any robot with a tile within r² 16 of the squeaker (GameWorld.java:1073-1083), and only to our own team and cats.
- The SYM squeak is gated on the king's *centre* within d2 16 (Baby.java:596), but babies deliver cheese from centre offsets (4,1) and (3,3), d2 17 and 18 (inTransferReach, Baby.java:1009-1012).
- The baby read loops at 576-579 and 586-589 decode only SQ_MINE.
- Do not hook TrapRisk.heard: it is skipped during cooperation and when fewer than 8000 bytecode are left (Baby.java:60-61).

**Changes.**
- `Cfg.java`: `SYM_HEAR_TILE = false`, `SYM_GOSSIP = false`, `SYM_GOSSIP_EVERY = 3`.
- `Baby.java`: add `static boolean kingHears(MapLocation p, MapLocation k) { int dx = Math.max(0, Math.abs(p.x-k.x)-1), dy = Math.max(0, Math.abs(p.y-k.y)-1); return dx*dx + dy*dy <= 16; }` next to `inTransferReach`.
- At the top of `report()` (Baby.java:572; s4d :555): compute `near` once. With `SYM_HEAR_TILE`, it is true if any of `Comms.kings[0..numKings)` passes `kingHears`; otherwise it keeps today's centre ≤ 16 test. Replace the three `k == null || d2 > 16` tests (577, 590) with `!near` and the `<= 16` test at 596 with `near`. Leave the SQ_CAT gate at 620 alone, to keep the experiment clean.
- In both read loops add `else if (Cfg.SYM_GOSSIP && Comms.sqType(c) == Comms.SQ_SYM) Sym.merge(Comms.sqExtra(c) & 7);`. Both GOSSIP flags are on, so one of the loops runs every turn. If both flags are ever off, add a `readSqueaks(G.round - 1)` loop. The enemy cannot inject squeaks, and merge rejects an empty result.
- Inside each gossip branch, after its read loop and before its mine squeak:
  ```java
  if (Cfg.SYM_GOSSIP && !near && sharper && (G.coop || nearestEnemy == null)
          && G.round - symSqueaked >= Cfg.SYM_GOSSIP_EVERY && allyWithin16() && !catEarshot()) {
      squeak(SQ_SYM, Sym.mask); symSqueaked = G.round; return;
  }
  ```
  where `sharper = shared != 0 && (Sym.mask & shared) != shared`. `allyWithin16()` scans `seen` (Baby.java:40) for `G.us` within d2 16. `catEarshot()` is true when the nearest visible cat (`cat`) has a body tile within d2 16.

**Bytecode.** About 15 per king for `near`; about 10 per heard SQ_SYM. The ally scan runs only while the baby is sharper and away from kings, which is rare.

**Unit test** (`testSymRelay`):
- The fake `readSqueaks` currently returns an empty array (:135). Make it return a `heard` list filtered by `roundNum == -1 || m.getRound() == roundNum`, and clear the list in `reset()`.
- Gate: me (5,5), king (9,6) (centre d2 17, tile d2 9), `shared[Comms.SYM]=7`, `Sym.mask=HOR`, `G.coop=true`. With `SYM_HEAR_TILE`, expect exactly one SQ_SYM with `sqExtra&7==HOR`; with it off, expect no SQ_SYM.
- Merge: `heard = [new Message(squeak(SQ_SYM,0,0,HOR|VER), 10001, round-1, (6,6))]`, mask 7. After `report()`, the mask is 6.
- Disjoint squeak: the mask is unchanged and `contradictions == 1`.
- Away squeak: king at d2 100, an ally at (6,6). Rounds r and r+3 squeak SYM; r+1 does not. With a cat at (6,7), no SYM squeak.

### #3 `SYM_MINELIST` (+ `SYM_MINE_SPACING`, king only)

**Basis.**
- Mines are engine-paired (GameWorld.java:192-195) and static.
- The list is append-only: only `addMine` writes slot MINE0 and up (Comms.java:96-101), and `readMines` rebuilds the list every turn (81-88), so a per-robot counter works.
- `Sym.record` overwrites `mem` (Sym.java:25). The dig writes only do `&= ~DIRT` (Flow.java:189, Nav.java:163/180, King.java:346/383), so new high bits survive them.
- The spacing rule relies on the validator (LiveMap.java:497, spacing 25). validate-maps is on by default locally; that the tournament server also validates is an assumption.

**Changes.**
- `Sym.java`: add `EXP = 112` (bits 16, 32 and 64 are `s << 4` for ROT, HOR and VER) and `static int listDone`. In `record()`:
  - write `mem[i] = v | (old & EXP)`;
  - after the `SEEN`/`unique` early return: `if (!mine) { int e = (old >> 4) & mask; if (e != 0) eliminate(e); }`.
  
  Add `listCheck()`, which handles each entry from `listDone` to `numMines - 1` like this:
  - Skip it if the mask is unique.
  - For each live s: compute `t = mirror(m, s)` and skip it if `t == m`.
  - If `t` is SEEN without MINE, call `eliminate(s)`. If `t` is unseen, OR `s << 4` into its mem.
  
  `known()` still tests SEEN only.
- `Baby.turn`, after `sense()` (Baby.java:38): `if (Cfg.SYM_MINELIST && Flow.left() > Cfg.BC_OPTIONAL) Sym.listCheck();`. A newborn skips it and retries next turn, because the counter does not advance.
- `King.turn`, after `readSqueaks()` (King.java:34) and before `publish()`: `Sym.listCheck()`. With `SYM_MINE_SPACING`, also, for each new entry and each live s, rule out s when `0 < mirror(new, s).distanceSquaredTo(mines[j]) < 25` for any j (including the entry itself). That is about 400 bytecode per new entry.

**Bytecode.** At most 16 × 3 × about 20 = about 1k per list change (`listCheck` with a full list); about 3 per newly seen tile in `record`.

**Unit test** (`testSymMineList`, 20x20, listed mine m=(3,4), twins ROT (16,15), HOR (3,15), VER (16,4)):
- `record(16,15)` without a mine, list m, `listCheck()`: the mask is HOR|VER and `!Sym.known(3+15*W)`.
- `record(16,4)` without a mine: the mask is HOR and `contradictions == 0`.
- Separate case: list m first, then `record(16,15, mine=true)`: the mask stays 7.
- King spacing: mines (3,4) and (16,13). mirror_ROT(3,4) = (16,15) is at d2 4 from (16,13), so the mask becomes HOR|VER.
